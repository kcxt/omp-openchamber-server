# R6: `get_session_lease` from a sessionless utility child

Tests: `test/contract/lease.test.ts` and the lease checks in `test/contract/entries.test.ts` (both binaries).

## Source

- `rpc-mode.ts` `case "get_session_lease"` (~2798): `{sessionIds: string[]}` → `probeSessionLeases` (`session/session-storage.ts:689`) → `{held:string[], unknown:string[]}`; non-array input is an error response.
- `isSessionLeaseHeld` (`session-storage.ts:673`) probes the OS lock without taking it. On Linux the lock is an **abstract unix socket** named from the lease path (`sessionLeasePath`, `:626`; Windows: named mutex; elsewhere an `flock` sidecar). The path is `<owners dir>/<session id>`, owners dir = `PI_TEST_SESSION_OWNERS_DIR` or the state dir, so children sharing that variable share leases; the OS drops a lease when its process dies. Ids are read from the transcript **header**, not the file name.
- A lease is claimed on first write (`#claimSession`, `session-manager.ts:1158`, called from the persistence path), so a session that has produced no assistant message holds none (R2).

## Recorded behaviour (real omp 18.19.0 local build, Linux)

- A writer child (one prompt) holds the lease; a second child that has **no session open** answers `get_session_lease{sessionIds:[id, <unknown uuid>]}` with `held:[id], unknown:[]`.
- **Latency: 0.2 – 0.3 ms for the first probe on a cold child, 0.06 – 0.07 ms average over 20 probes in a row** (stdio round trip, printed by `lease.test.ts`). No spawn per probe is needed once a utility child is up; the cost is the child's startup (~1.7 s cold for `bun … cli.ts --mode rpc`, measured until `get_available_models` answered).
- The holder itself reports its own lease as held.
- After the holder is SIGKILLed the lease is gone on the next probe (abstract sockets die with the process): `held:[]`. A crashed owner never blocks.
- **Open-but-unwritten gap confirmed.** A child that has `switch_session`ed onto a fixture and written nothing holds no lease: the probe returns `held:[]`. The lease appears with the first write (a prompt turn; `set_session_name` also wrote in the real run). A terminal omp sitting at its prompt on an existing session is invisible until it writes, so lease-first status reads such a session idle; PLAN §3.13's "known gap" is about the opposite case; this one is an additional hole the P3 `claimLease` patch closes only for the sidecar's own children.
- `new_session`, `fork` and `switch_session` to a missing path take the lease immediately (the file is forced into existence); a fork's lease is the **fork's** id. In the test the parent had not written, so it stayed unheld; what a fork does to a lease the parent's process already holds was not run (`branch` lease not probed either).
- `unknown` was always empty in these runs (it lists ids whose lease cannot be probed).

## Consequences

- `Utility.leaseHeld(id)` is cheap and exact for "does a process hold this session": use it first; `false` → idle regardless of the tail (§3.5) is correct for crashed owners (the point of the design) and wrong only for an open-but-unwritten terminal session, where the tail is, by definition, not mid-turn.
- The probe must use the same `PI_TEST_SESSION_OWNERS_DIR` as the owners (test harness only; production resolves the state dir identically for every omp).
