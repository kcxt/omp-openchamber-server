# R5: moving a session to another directory without a driven prompt

Decision: **use omp's own `/move <dir>`, sent as an RPC `prompt` from a child that has the session open. No model call, no sidecar header rewrite.** Tests: `test/contract/tree.test.ts` "R5" (3 tests, both binaries).

## What `modes/move-directory-source.ts` is

Only the directory-completion source for the TUI move overlay (`resolveMovePath`, `listChildDirectories`, `moveDirectorySource.search`). It moves nothing and is not reachable from RPC.

## What actually moves a session

- `SessionManager.moveTo(newCwd, targetSessionDir?)` (`session/session-manager.ts:2576`): computes the destination bucket (`computeDefaultSessionDir`), refuses if another live process writes the source or holds the destination session's lease (`SessionMoveRefusedError`, "Cannot move session … another live omp process writes it. Nothing was moved."), renames the file (copy across devices on `EXDEV`) and its artifacts directory, rewrites the header (`cwd`, and `previousSessionFiles` gets the old path, `session-manager.ts:2734`), rolls back on failure. It needs a live `SessionManager`, so it cannot run on a path alone.
- `AgentSession.moveSession` (`session/agent-session.ts:12624`) wraps it. No RPC command exposes it (no `move` case in `rpc-mode.ts`).
- The builtin slash command `/move <path>` (`slash-commands/builtin-lifecycle.ts:758`) has a headless handler, `relocateHeadlessSession` (`:95`): flush settings, `moveSession`, `setProjectDir(resolvedPath)` (re-scopes the whole process: tools and cwd now point at the new directory), `rescopeHeadlessToCwd`, then `command_output "Moved to <dir>."`. RPC `prompt` runs builtin commands through `executeAcpBuiltinSlashCommand` (`rpc-mode.ts` `dispatchOrderedUserInput`), so it works over stdio.

## Recorded behaviour (real omp)

`switch_session {sessionPath: <fixture>}` on a sessionless child, then `prompt {message: "/move <dest>"}`:

- Response `{success:true, data:{agentInvoked:false}}`, preceded by `config_update`, `session_info_update{sessionId}` and `command_output{text:"Moved to <dest>."}`. No `agent_start`, no `prompt_result`, no model request (provider request count unchanged).
- The file moved into the destination's bucket (`sessions/-other/<same filename>`); the old path is gone; `get_state.sessionId` is unchanged; header `cwd` is `<dest>`, `previousSessionFiles: [<old path>]`; all entries and ids intact.
- While another process holds the session's lease the command fails softly: `command_output "Move failed: Cannot move session "<file>": another live omp process writes it. Nothing was moved."` and the response is still `success:true, agentInvoked:false`. **The failure is only visible in `command_output`**, so the sidecar must read it (and re-check `get_state.sessionFile`) rather than trust the response.
- A missing target: `command_output "Directory does not exist: <dest>"`, nothing moved.

## Consequences for the rewrite

- Utility child flow for `PATCH /session/:id {directory}`: `switch_session` → `prompt "/move <dir>"` → read `command_output`/`get_state.sessionFile` → close that child (it is now re-scoped to the destination and holds the session's lease until it exits, so keep it only if a runtime for the session is wanted there).
- It takes the lease for the duration, so a probe-then-move race is closed by omp itself; an owned-elsewhere session is refused without a pre-check.
- `/move` is refused while streaming ("Cannot move while streaming.").
- The single documented sidecar header rewrite PLAN §3.9 reserved for this is unnecessary.
