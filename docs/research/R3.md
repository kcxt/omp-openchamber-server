# R3: `navigate_tree` as revert/redo

Tests: `test/contract/tree.test.ts` "R3 navigate_tree" (both binaries). Fixture: hand-written transcript `u1 a1 u2 a2 u3 a3` (`writeFixture` in `test/contract/harness.ts`), opened with `switch_session`.

## Source

- `rpc-mode.ts` `case "navigate_tree"` (~2260): validates `entryId` (`entry_not_found`), refuses while `session.isBusyForSnapshot` (`session_busy`, `session/agent-session.ts:8199`), then `session.navigateTree(entryId, {requireIdle:true, summarize:false})` and answers `{cancelled, aborted, editorText}`. A re-answer of an `ask` entry is refused (`ask_reanswer_unsupported`).
- A user-message target moves the leaf to its **parent** and returns the text as `editorText`; any other target becomes the leaf itself.

## Recorded behaviour (real omp)

| Step | `get_messages` after | `get_entries.leafId` | Transcript file |
|---|---|---|---|
| `navigate_tree u2` → `{cancelled:false, editorText:"question 2"}` | `q1 a1` | `a1` | byte-identical to before |
| `navigate_tree a3` (redo) → `{cancelled:false}` (no `editorText`) | all six | `a3` | byte-identical |
| `navigate_tree a1` | `q1 a1` | `a1` | unchanged |
| `navigate_tree zzzz` | | | `{success:false, code:"entry_not_found", error:"Entry zzzz not found"}` |
| navigate during a live run | | | `{success:false, code:"session_busy"}` |

`get_entries.entries` still lists all six entries after a revert: the abandoned branch is never removed.

**The revert is not durable until something is appended.** `navigate_tree` writes nothing: no `branch_summary`, no leaf marker. A second omp opened on the file after the revert reports `leafId = a3` (the last line) and the full history. The next append (a prompt) is journaled with `parentId` = the new leaf, via a chain of bookkeeping entries that passes through `a1` and never through `u2`; from then on the file carries the new branch (`get_messages` in a fresh process: four messages, no `question 3`) and the old one stays reachable by `navigate_tree a3` in the owning process.

## Mapping to OpenChamber

- Revert to message M = `navigate_tree(parentOf(M))`, or `navigate_tree(M)` itself, which returns the same parent-leaf and the editor text. Redo = `navigate_tree(<abandoned leaf id>)`. The sidecar must therefore keep the abandoned leaf in `SessionDoc.revert.redoLeafId` (PLAN §3.10), as planned.
- Because the leaf is process memory until the next append, a child that dies between a revert and the next prompt loses the revert silently (the file still ends at `a3`). Either re-issue `navigate_tree` whenever a runtime is created for a session whose `SessionDoc.revert` is set, or compare `get_entries.leafId` against the doc after `switch_session`.
- `TranscriptReader` showing "the active branch" must use the same rule omp does (path from the last line's id) for undriven sessions, which is exactly why a not-yet-persisted revert is invisible to followers.
